# Maligator 0.1.0-alpha.32

Alpha.31 could crash before the first line of a program ran. The collector initialized
before the heap it collects, and already retired the heap's allocation cursors, reading
them from whatever bytes the VM's storage held. Most programs happened to find zeros
there. A program linking a native library, which changes what the stack holds before
`main`, could find stale pointers instead and stop with a segmentation fault in
`mal_gc_init`. Production executables and `maligator run` were both affected (#93).

## Fixes

- The collector no longer touches the heap while it initializes; the heap establishes
  its own initial allocation state. A native regression starts and tears down a host
  program in VM storage filled with stale bytes, with and without GC stress.
- Native builds reuse compiled C objects across toolchains that differ only in their
  C++, archive, Rust or link tools, instead of compiling them again.

Maligator remains a pre-1.0 alpha. The native packages are unsigned and unnotarized;
APIs and internal contracts may change.
