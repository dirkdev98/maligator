# Maligator 0.1.0-alpha.31

Alpha.30 carried Core's facts through native lowering and kept records out of the heap.
The runtime underneath still did quite some generic work. The collector promoted
everything allocated while a major cycle marked, interpreted code dispatched every
instruction through one switch, compiled calls shared one indirect branch, and strings,
development images, HTTP headers and JSON nesting had fixed ceilings. This alpha works
on those, and fixes the two failures reported against the alpha.30 npm packages.

## Highlights

- Keep cells allocated during a major cycle young instead of promoting them, and start
  a major once minors have promoted enough instead of on a fixed cadence. Managed cells
  are tracked in per-block bitmaps and the common allocation path runs inline. The
  longest pause while the compiler compiles itself drops from 2.9 to 0.7 s.
- Rewrite each binary operator into an operator-specific instruction when an image
  loads, fuse a comparison with the jump that tests it, and dispatch through a table of
  handler labels on GNU C builds. Interpreted calls reach native functions and known
  primordials directly. The four interpreted JavaScript modes now take 24 to 41% less
  time.
- Pick the compiled callee at each call site instead of in one shared dispatch, and
  call script methods named like `Map` and `Set` methods, such as Express's `res.set`
  and `req.get`, without the collection dispatcher.
- Build object and small array literals, construct receivers and entry pairs inline,
  and reclaim dead inline Arrays without a finalizer call.
- Defer pure record graphs a function returns until they escape, keep integer
  accumulation and `Math.imul` in int32, run nested record iterations in numeric
  regions, select strings from finite integer domains and sort by numeric record
  fields in native kernels.
- Concatenate strings and template parts without generic coercion, format int32
  strings and short `toFixed` results straight into inline cells, round `toFixed`
  exactly in 128 bits, and run lazy single-class RegExp loops without allocating.
- Reuse canonical Promises during `await`, settle `Promise.all` through typed element
  reactions, wake kqueue reactors with a user event instead of a pipe and wake one
  executor worker per submitted job.
- Remove fixed ceilings. A string now holds up to 2,147,483,647 UTF-16 code units
  instead of 33,554,431, and development images, generated sources, HTTP response
  headers, dgram buffer lists, watched directory trees and test subprocess output grow
  with what they hold. JSON parsing, revivers and `JSON.stringify` continue past the
  native stack, so 100,000 levels of nesting work in both backends.

The release fixes both failures reported against the alpha.30 packages from npm.
`readFileSync(path, "utf8")` reads a 22 MB file (#82), and a development build of a
program with thousands of small functions no longer fails with `Invalid string length`
while generating its fragment units (#83). It also keeps isolate ownership when a worker
joins, retains every configured DNS nameserver, erases object type operands in return
types, and fixes collector edge cases around conservative lookups, allocation cursors and
old raw storage growth.

## Refreshed benchmark snapshot

The five-sample snapshot in `bench/baseline.json` measures clean source `e78bad87`.
JavaScript phase checksums matched Node, and the self-compiled compiler emitted the same
code as the Node-hosted one.

| Workload                       |      Snapshot | Alpha.30 snapshot |
| ------------------------------ | ------------: | ----------------: |
| JavaScript, closed compiled    |      284.4 ms |          291.8 ms |
| JavaScript, open compiled      |      410.4 ms |          421.0 ms |
| JavaScript, closed interpreted |    2,077.7 ms |        3,079.2 ms |
| JavaScript, open interpreted   |    2,397.4 ms |        3,352.5 ms |
| JavaScript v2, closed compiled |      397.9 ms |          710.3 ms |
| Bare HTTP                      | 226,421 req/s |     198,081 req/s |
| Express routes                 |  61,245 req/s |      62,715 req/s |
| Express JSON                   |  48,656 req/s |      50,452 req/s |
| Express form                   |  39,481 req/s |      41,054 req/s |
| Native compiler execution      |       128.0 s |           120.8 s |

Node ran the JavaScript workload in 359.9 ms on the same laptop, so closed compiled code
takes 0.79x its time. On the twelve-phase JavaScript v2 workload closed compiled code
now beats Node's 428.4 ms as well.

Bare HTTP serves 1.57x Node's 144,358 req/s. Express routes stay ahead of Node's 54,211
req/s, JSON reaches 0.99x of its 49,387 and form 0.91x of its 43,596. Express
throughput dropped 2 to 4% against the alpha.30 snapshot. That is most likely the new
major policy: the server ran 727 collections instead of 2,956, but its resident size
rose from 32 to 79 MiB and its p99 latency by about 20%.

The self-compile workload emits 192,271,750 code units across 170 translation units,
against 180,075,487 across 148 for alpha.30. The native compiler takes 2.2 times the
58.6 s of the Node-hosted one, where alpha.30 took 2.3 times, and its peak resident size
fell from 6.4 to 6.0 GiB. Node moved from 26.12 to 26.13 between the two snapshots.

Maligator remains a pre-1.0 alpha. The native packages are unsigned and unnotarized;
APIs and internal contracts may change.
