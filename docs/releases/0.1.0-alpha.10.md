# Maligator 0.1.0-alpha.10

This alpha introduces an opt-in Temporal runtime, executes the complete applicable
Test262 corpus, and fixes the remaining release-blocking application builds.

## Highlights

- Added the Stage 4 `Temporal` namespace on top of `temporal_rs`, including core
  duration, instant, plain date/time, zoned date/time, calendar, and system time-zone
  behavior. Product builds opt in with `engine.temporal`; builds that leave it off do
  not carry the Temporal calendar and time-zone data.
- Integrated Temporal with the existing ICU4X-backed internationalization layer and
  shared Rust runtime archive, keeping one provider and one native linkage path.
- Removed the remaining Test262 skip manifests and now execute the full applicable
  strict and sloppy corpus. The release baseline records 50,319 passing tests and
  3,063 known failures, with no hidden skipped sections.
- Added `SuppressedError`, `Date.prototype.toTemporalInstant`, `Symbol.dispose`,
  `Symbol.asyncDispose`, and iterator disposal behavior.
- Implemented Annex B legacy String HTML methods, `escape`/`unescape`, and legacy
  Date methods exposed by the newly unlocked corpus.
- Preserved callable CommonJS default exports in interpreted `maligator:test`
  fragments, fixing direct Express default imports (issue #28).
- Split oversized generated function and source-position tables into bounded native
  translation units, allowing very large applications to compile and link (issue
  #29).

## Support

This release candidate is intentionally built and packaged only for macOS arm64:

- `@maligator/cli`
- `@maligator/cli-darwin-arm64`
- `maligator-v0.1.0-alpha.10-aarch64-apple-darwin.tar.gz`

The launcher requires Node.js 20 or newer. Applications built with Maligator require
the Rust toolchain pinned by the repository and a C23-capable C compiler.
Web-platform applications also require a C++ compiler and runtime.

## Release integrity

- The immutable GitHub prerelease contains the exact checked npm tarballs and
  `packages.json` checksum manifest produced on the release host.
- Publishing is performed by the repository's GitHub Actions workflow through npm
  trusted publishing with a short-lived OIDC identity and no stored npm token.
- Platform packages are published before the launcher package; matching registry
  integrity allows an interrupted workflow to resume without replacing artifacts.
- Packed package contents, SHA-256 digests, host execution, and an isolated launcher
  installation are checked before the GitHub release is published.

## Known limitations

- Temporal remains opt-in for product builds because its calendar and time-zone data
  materially increase the runtime payload.
- Several advanced Temporal and Intl behaviors remain represented by known Test262
  failures; the complete corpus is now visible and tracked for incremental fixes.
- The interpreted-test `fetch` surface currently covers local HTTP
  request/response workflows; HTTPS, redirects, streaming bodies, aborts, and
  automatic decompression remain deferred.
- macOS x64, Linux arm64/x64, and Windows binaries are not included in this alpha.
- Alpha binaries are unsigned and are not notarized.
- The minimum supported macOS version is not yet fixed.
- Runtime eval accepts JavaScript; TypeScript erasure for runtime eval remains
  deferred.
- The approval-only `test:full:report` release gate has not been run for this
  candidate; the complete compiled Test262 strict/sloppy corpus was run separately.
- This is a pre-1.0 alpha; APIs and internal contracts may change.

Report problems at <https://github.com/dirkdev98/maligator/issues>.
