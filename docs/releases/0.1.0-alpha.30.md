# Maligator 0.1.0-alpha.30

Alpha.29 kept compiled values in C locals and guarded class members on shared layouts.
The native backend still lost most of what Core proved about a value once it lowered an
instruction, objects handed between functions still lived on the heap, and RegExp, JSON
and HTTP requests went through general runtime paths. This alpha works on those, and
fixes the two build failures reported against the alpha.29 npm packages.

## Highlights

- Carry Core's facts about operands, results and effects through native lowering
  independently of each other: kinds, integer ranges, identities, String lengths,
  Symbol keys, reachability and collection brands. Native code uses them to drop
  guards, GC roots and dead branches, and to keep int32 values in integer storage.
- Return records to callers that only read their fields, and hand object literals to
  callees that take record parameters, in the caller's storage instead of a heap
  object. Field kinds and integer bounds travel with the record.
- Run more loops in unboxed numeric regions: integer sums and TypedArray arithmetic in
  integer locals, loops over exactly typed views and DataView accessors, `charCodeAt`
  scans, inner loops inside their enclosing region, and bounds offset by a constant.
- Call bound functions, `apply` with a fresh array literal and methods read from
  object literals directly, pass spread Array literals as positional arguments, and
  create closures from one cached shape.
- Match, test, split and replace through canonical RegExp objects without generic
  property access, and share one compiled matcher between the objects of a regex
  literal. Parse short JSON integers and repeated keys from their source bytes, and
  keep `JSON.stringify` shape plans across calls.
- Sort arrays by insertion blocks and ordered runs, look up int32 and identity Map and
  Set keys inline, change the case of ASCII strings a word at a time, and bound decimal
  formatting to its rounding prefix. Minor collections visit only recently inserted
  atoms.
- Trim per-request work in `Mal.serve` and the Node HTTP server: build a served
  Request's members on first read, reuse per-request native state and deliver a whole
  request in one turn. `ServerResponse.writeHead`, `_header` and `'close'`, client
  failures, agents and `resetAndDestroy` now behave as in Node.
- Link JavaScript and the emitted C side by side in the Explorer.

The release fixes two build failures in the alpha.29 packages from npm. A development
build no longer looks for the compiler sources on the machine that built the release
(#80), and a production build with a file asset of a few megabytes no longer fails with
`Invalid string length` (#81). It also keeps recent atoms when the atom store grows,
rejects an interpreted async body's early throw instead of unwinding into its caller,
reads `RegExp.lastParen` from the pattern's last group and checks Proxy call and
construct capability before running traps.

## Refreshed benchmark snapshot

The five-sample snapshot in `bench/baseline.json` measures clean source `aab42fb1`.
JavaScript phase checksums matched Node, and the self-compiled compiler emitted the same
code as the Node-hosted one.

| Workload                       |      Snapshot | Alpha.29 snapshot |
| ------------------------------ | ------------: | ----------------: |
| JavaScript, closed compiled    |      291.8 ms |          358.2 ms |
| JavaScript, open compiled      |      421.0 ms |          438.3 ms |
| JavaScript, closed interpreted |    3,079.2 ms |        3,422.1 ms |
| JavaScript, open interpreted   |    3,352.5 ms |        3,587.0 ms |
| Bare HTTP                      | 198,081 req/s |     184,882 req/s |
| Express routes                 |  62,715 req/s |      51,565 req/s |
| Express JSON                   |  50,452 req/s |      36,570 req/s |
| Express form                   |  41,054 req/s |      29,366 req/s |
| Native compiler execution      |       120.8 s |           108.2 s |

Node ran the JavaScript workload in 357.7 ms on the same laptop, so closed compiled code
now takes 0.82x its time. Express routes and JSON overtake Node's 54,783 and 49,441
req/s; form reaches 0.94x of its 43,746.

The snapshot adds the twelve-phase JavaScript v2 workload, which covers records, dynamic
objects, calls, arrays, collections, text, JSON, numbers, binary data, iteration, async
code and allocation. Closed compiled code runs it in 710.3 ms against Node's 422.4 ms.

The self-compile workload emits 180,075,487 code units across 148 translation units,
against 149,936,194 across 129 for alpha.29. The native compiler takes longer because
there is more to compile, but it stays at about 2.3 times the 53.4 s of the Node-hosted
one.

Maligator remains a pre-1.0 alpha. The native packages are unsigned and unnotarized;
APIs and internal contracts may change.
