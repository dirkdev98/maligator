# Maligator 0.1.0-alpha.3

This alpha expands Node.js application compatibility and removes several build-time
barriers found while compiling Express-based applications.

## Highlights

- Added `node:async_hooks` `AsyncLocalStorage` compatibility, including Node 26
  behavior for context propagation, `bind()`, and `snapshot()`.
- Split generated native C across bounded translation units, avoiding oversized
  generated-source strings and producing bounded diagnostics for indivisible units.
- Preserved catchable `MODULE_NOT_FOUND` behavior for optional CommonJS
  `require()` calls inside `try`/`catch`.
- Expanded application-module TypeScript erasure to Node 26-style erasable syntax,
  including inline type imports, generics, typed arrows, assertions, class syntax,
  ambient declarations, and type-only namespaces.
- Separated eval runtime behavior from source auditing: `engine.eval: false` now
  compiles dynamic-code sites that throw if executed, while `"compile-check"`
  rejects statically visible uses during the build.

## Support

This release candidate is intentionally built and packaged only for macOS arm64:

- `@maligator/cli`
- `@maligator/cli-darwin-arm64`
- `maligator-v0.1.0-alpha.3-aarch64-apple-darwin.tar.gz`

The launcher requires Node.js 20 or newer. Applications built with Maligator require
the Rust toolchain pinned by the repository and a C23-capable C compiler.
Web-platform applications also require a C++ compiler and runtime.

## Known limitations

- macOS x64, Linux arm64/x64, and Windows binaries are not included in this alpha.
- Alpha binaries are unsigned and are not notarized.
- The minimum supported macOS version is not yet fixed.
- Runtime eval accepts JavaScript; TypeScript erasure for runtime eval remains
  deferred.
- The approval-only `test:full:report` release gate has not been run for this
  candidate.
- This is a pre-1.0 alpha; APIs and internal contracts may change.

Report problems at <https://github.com/dirkdev98/maligator/issues>.
