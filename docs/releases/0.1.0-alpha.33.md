# Maligator 0.1.0-alpha.33

Maligator can call C libraries. Declare a library in the build config and Maligator reads
its headers with clang and compiles a binding into the application, so the C compiler
handles calling conventions, structs passed by value and macros. Earlier alphas carried
this support without announcing it. This alpha makes those calls cheaper, binds more of
the APIs that Dear ImGui, cimplot and WebGPU expose, and fixes the failures reported
against alpha.32. The [C libraries guide](https://maligator.ddv.tools/guides/c-libraries)
describes the contract.

## C libraries

- Production builds generate a binding from the exports a program reads, so unread
  destructors, callback machinery and accessors stay out of the executable. A program
  whose imports register no callbacks compiles its C calls without callback reentry.
- Calls cost less. Typed arrays lend their storage to C without a copy, and compiled
  numeric loops hand a fixed view's storage straight to the C function. Scalar fields of
  struct handles read without calling their getter, and `using` scopes dispose without
  allocating. An 8-element `Float64Array` dot product in a loop drops from 8.2 to 1.4 ns
  per call, against 1.5 ns for plain C, and opening, reading and disposing a handle from
  about 100 to 63 ns (indicative, laptop on AC).
- New contract facts:
  - `length: "width * height * 4"` requires a buffer of at least that many bytes and
    keeps every factor in the JavaScript signature.
  - `end: "text"` passes the end of a string parameter, for `[text, text_end)` APIs.
  - `array: { length: "count" }` on a handle field reads a counted array of records,
    such as Dear ImGui's sort specs, from a library-owned struct.
  - `pointee: "double"` types a `void *` parameter, and functions that are not variadic
    accept `variants`, so each value type gets its own export.
  - A pointer result of a struct that is also passed by value returns a handle around the
    library's struct, as cimplot's `ImPlotSpec` needs.
  - `once: true` keeps a callback until the library's one call, and `field` passes a
    JavaScript function inside a struct passed by value, such as WebGPU's callback info
    records.
- Header models stay cached for libraries such as OpenSSL whose macros expand to
  `__FILE__`, and planner errors name the fact path at fault.

## Compiler and runtime

- Each ES module instantiates in a function of its own, module bindings read as SSA
  values, and a closed program emits no native code for functions it never creates.
- Property loads keyed by well-known symbols, such as `obj[Symbol.iterator]`, hit the
  property cache, and class getters and field definitions take faster paths.

## Fixes

- A development executable resolves a CommonJS import from another image to the right
  module, so `import express from "express"` creates an application again (#92, #94).
- An array chosen by a condition between literals of different lengths keeps its own
  `length` instead of folding to 0 (#95).
- TypeScript stripping keeps the body after a type predicate that names an object type
  and strips arrows with parenthesized return types. Untyped arrow parameters inside a
  typed function, and conditionals whose branches are arrows, no longer lose code.
- `import()` and `import * as` namespaces of a CommonJS module include names it
  re-exports through TypeScript's `__exportStar`, Babel's star export loop or a `require`
  spread.

Maligator remains a pre-1.0 alpha. The native packages are unsigned and unnotarized;
APIs and internal contracts may change.
